## 三、本次新发现问题

### 🔴 严重 / 🟠 高危 / 🟡 中危

**无。**

### 🟢 低危（1 项）

**L1. `_ocr_pdf` 本地 OCR 路径无逐页容错——PIL 解码失败 / 子进程超时以英文技术串进入 doc.error**
`_ocr_pdf` 的页循环对 OCR 调用无 try 包裹（对照 `_ocr_pdf_pages` 有逐页 `except: continue`，两函数行为不对称）：本地路径下 ① `Image.open` 遇损坏内嵌图抛 PIL 异常、② `subprocess.run` 超时抛 `TimeoutExpired`——异常直接冒泡到 `process_document` 的 failed 落库，错误信息形如 `Command '['C:\\Program Files\\...tesseract.exe', ...]' timed out after 180 seconds'`（英文 + 完整命令行路径），违背 README/AGENTS「全部中文友好提示」约定；视觉模型路径此前无此问题（`_vision_describe` 自带中文 RuntimeError）。建议：页循环内捕获 `TimeoutExpired`/PIL 异常转中文 RuntimeError（「本地 OCR 超时（180 秒/页）/ 图片解码失败，已跳过该页或终止」），并顺手对齐两函数的逐页容错策略。一行 try 级修复。

### ℹ️ 提示（非问题）

- **agent_log 无本地 OCR 观测行**：tesseract 路径不产生 slot 日志（无 AI 调用，失败原因已入 doc.error）——若追求与 CH-080（rerank）同等的可观测性，可加 slot="ocr_local" 行记录页码/耗时/文本长度；非必需。
- **LOCALAPPDATA 缺失时的相对路径候选**：`os.path.join("", "Programs\\...")` 产生相对路径并按 CWD 解析——现实触发概率趋零，加固建议：候选仅接受绝对路径（`os.path.isabs` 过滤）。
- **TESSDATA_PREFIX 按「traineddata 所在目录」约定**：与 Tesseract ≥5 及 README 口径一致；旧教程「指向父目录」写法的用户会误报缺失——错误信息已引导到 README 正确姿势，可接受。
- **`chi_sim+eng` 缺 eng 时**：返回码非零、stderr 已入错误信息（可读）；可选优化为 chi_sim 单语言回退，非必需。
- **长扫描件总时长**：本地 OCR 每页超时上限 180s，30 页扫描件最坏 90 分钟占用解析 worker——演示规模可接受；如需可在设置页提示「页数 × 单页耗时」预估。
- **local_ocr 全槽位冗余落盘**：与 enabled 同款模式（collectAiItem 全量发送、put_ai 对其他槽位也写 False）——既定接受的无害冗余。
- **文档同步履行完整**：分类表（升格流程第三轮通过）、TC-151、README 安装指引（含免提权）、CH-090 登记、版本记录、API 例行升版——CH-062 前置义务全数履行。

## 四、优点

1. **「系统级复用优先于引入依赖」的路线纪律**：OCR 缺口本可用 pytesseract/easyocr/paddleocr 补，最终选择「标准库 subprocess + 用户自装 Tesseract」，零依赖增重、零打包体积增长（对照 pymupdf +20MB），且与既有的 PaddleOCR 排除决策逻辑自洽——这类取舍在方案文档/CH/代码注释三层口径一致。
2. **子进程调用是教科书式写法**：参数数组、超时、输出捕获、编码容错、临时目录清理五个要素齐备；双探针以「文件存在性」而非版本号猜测，错误信息即安装指引（可直接复制执行的 winget 命令）。
3. **失败即自解释的产品化细节**：勾选开关但环境缺失时，用户得到的不是静默降级也不是英文堆栈，而是带修复命令的中文提示（TC-151② 固化该断言）——失败路径与成功路径同等被设计。
4. **整改闭环连续三轮高质量**：v0.1.44 三项（含一行级 L1 收紧、末列落单成句的语义修复）全部按建议落地且带 CH-088 注释锚点，回归时「评审编号 → 代码位置」可一键对照——评审-整改链路的可追溯性已成熟。
