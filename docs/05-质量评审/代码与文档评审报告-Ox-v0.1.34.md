设计要点：
- **escAttr 独立函数而非改 esc() 本体**：文本位继续用宽松转义不受影响，属性位显式加强，职责清晰

- **重试幂等兜底**：即便双击造成双次入队，0.1.32 的 clear_chunks 保证最终切片不重复（见 L4 残余说明）

## 三、本次新发现问题

### 🔴 严重 / 🟠 高危 / 🟡 中危

**无。**

### 🟢 低危（4 项代码）

**L1. 后端 415 错误文案未同步 office 扩展名（0.1.30 引入，前两轮评审未捕获）**
`backend/app/routers/docs.py:28`：拒绝信息仍写「支持：txt / md / pdf / docx / 图片（png、jpg、jpeg、webp、bmp、gif）。」，漏列 0.1.30 新增的 `.doc .wps .xls .xlsx .ppt .pptx` 六种。与 API说明文档 §2.1 错误示例（已列全量白名单）及 index.html 工具栏提示（已列全量）三方不一致——用户上传不支持类型时看到的提示反而比文档旧。建议补齐该字符串（或改为由 `ALLOWED_EXTS` 动态生成杜绝再次漂移）。

**L2. Cargo.lock 再次滞后：停在 0.1.32 ≠ 三处主体的 0.1.34**
`shell/src-tauri/Cargo.lock:1953`。0.1.32 曾随发版构建刷新，但 0.1.33/0.1.34 两次升版只改了 package.json/Cargo.toml/tauri.conf.json，未跑 cargo check 刷 lock。与上轮 L15 同根：**版本号核对清单的第 4 处尚未固化进升版动作**。建议：升版 checklist 明确"cargo check 刷新 lock"步骤，或在 H4 断言中把 lock 一并纳入（允许滞后则显式豁免并注明）。

**L3. requirements.txt 头注释 v0.1.32 ≠ 当前 0.1.34**
`backend/requirements.txt:1`。依赖本身无变化，纯注释滞后；随下次发版顺手改即可。

**L4. 重试双击 TOCTOU：并发 retry 可双次入队**
docs.py:88-93 的 check-then-act 非原子：两个并发请求均可读到 failed → 各置 queued/各 enqueue 一次 → 同一文档被两个 worker 先后解析两遍。因 M4 幂等化，最终数据一致，仅浪费一次解析；且 FastAPI 同步端点线程池下窗口极窄。如需彻底封死可将"校验+置 queued"合并为一条条件 UPDATE（`WHERE status='failed'`）按受影响行数判定。
