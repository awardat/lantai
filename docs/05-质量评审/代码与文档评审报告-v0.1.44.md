## 三、本次新发现问题

### 🔴 严重 / 🟠 高危

**无。**

### 🟡 中危（1 项）

**M1. 3 列表格末列数据静默丢失——kv 路径奇数宽度丢列，且 CH-085 登记口径（≥3 列列式）与实现（≥5 列）不一致**
`_kv_to_nl` 的取对循环 `range(0, len(r) - 1, 2)` 只覆盖偶数宽度：nc=2 → (0,1) ✓；nc=4 → (0,1)(2,3) ✓；**nc=3 → 仅取 (0,1)，第 3 列被静默丢弃**；nc∈{2,3,4} 走 kv 路径（`header = rows[0] if nc >= 5 else None`），故 3 列表（名称/等级/备注类，现实常见）的末列不进索引、检索永远命中不到该列内容——确定性数据丢失且无任何日志。另查登记口径：CH-085 行写「列式表（**≥3 列**）走 `_table_to_nl`」而实现与 §4.3 文档均为「≥**5** 列」——若按登记口径实现则 3 列表本应走列式不受影响，说明登记与代码有一方失真（代码为先）。建议二选一修复：① kv 循环改为遍历 `range(0, len(r), 2)` 并对末列落单时以「{表名}：{r[i]}」单独成句（或该列并入前对）；② 奇数宽度（nc=3）直接改走 `_table_to_nl` 列式（首行作表头）。同时把 CH-085 行的「≥3 列」更正为实际口径，杜绝下轮回归比对时的口径混乱。

### 🟢 低危（3 项）

**L1. `same_section` 第三分支与自身注释矛盾：回退名表格遇新节标题仍被误接续**
代码注释/docstring/CH 均声明「节标题变化 = 新表（避免 4.1 表误接续 4.2 表）」，但 `same_section` 的第三分支 `open_tab["name"].startswith("第")` 使**上一表为「第N页表格」回退名**（该页无节标题时产生）时，后续页即使出现新节标题（如「5. 变更记录」）也恒为 True → 列数一致即误接续。触发前提较窄（前页有表但无节标题 + 后页新节标题 + 列数恰好相同），后果为 NL 串表与页码元数据失真（不崩溃）。建议：第三分支收紧为 `(open_tab["name"].startswith("第") and not section)`——「两边都无节标题才沿用」，与注释语义对齐。

**L2. 每次预览文本降级都全量重跑 pdfplumber 双策略——文本预览路径延迟明显上升**
`pdf_text_layers` 在解析（一次性）与**预览**（docs.py:124，每次点击都执行）两处调用，本轮起每次调用都对全部页面跑 pdfplumber 默认 + text 两轮 `extract_tables()`（外加每页 `extract_text`）——35 页表格密集 PDF 的预览文本组装可能新增数秒级延迟。主预览路径（iframe 原生查看器加载 raw）不受影响，但文本降级/复制场景可感知。建议：模块级按 `(path, mtime)` 缓存 `pdf_extract_tables_nl` 结果（解析与预览共享），或预览路径跳过表格增强（入库时 NL 行已并入切片）。演示规模可接受，登记备查亦可。

**L3. `_merge_cell_lines` 英文行尾接续不补空格——跨行英文粘连成词**
终止符集不含英文字母（合理：中文单元格以字母收尾通常需接续），但英文单元格「ISO 27001\nInformation Security」会被拼接为「27001Information Security」。中文无空格书写习惯下无碍，涉外文档会产出粘连伪词。建议：接续时若 prev 尾与 ln 首均为 ASCII 字母/数字则插入空格（一行条件）。

### ℹ️ 提示（非问题）

- **打包核验提醒（自测清单第 2 条既定义务）**：pdfplumber 引入传递依赖 **pypdfium2**（含平台二进制）与 charset-normalizer 等——requirements 无需手写传递依赖，但发布构建后需按惯例核对 PyInstaller `_internal` 产物含 pypdfium2 dll 并跑一次样本 E2E。
- **版本记录预写发布目录第四版沿用**（`lantai-shell-0.1.44-*` 已标当前版本，磁盘未构建）——该节奏已与发布确认流程形成默契，维持既往结论：CI 化时统一改脚本回填。
- **`_row_break_join` 阈值 0.6 与终止符集**属调参空间，TC-148 样本已覆盖正反例，无需动作。
- **接续后 `last` 指针在"纯重复表头页"分支不更新**：极窄边界（连续两页纯表头）下第三页的 break-join 判定基于更早一行——最坏多拼一次，启发式域内可容忍。
- **文档同步全面到位**：技术对接方案本轮新增机制行（升格流程首个成果）、API V1.42 例行升版（接口形状未变）、TC-148 断言含具体 NL 句样例与已知局限清单、CH-085 登记含三难点对策原文与实现对照——CH-062 前置同步义务履行完整。

## 四、优点

1. **三难点对策完整且可测**：①换行合并 ②跨页表头 ③行打断全部落地，并以真实 35 页调查表样本写进 TC-148 断言（具体 NL 句、目录零残留、None 零残留）——「登记的已知局限（竖排 label 切列）」与「宣称的能力边界」划分清晰，诚实度高。
2. **双策略择优是本轮最聪明的设计**：对无框线 label:value 调查表，lattice 造假结构、text 对齐反而正确的判断来自真实样本对照，择优规则（非空单元格计数）简单可靠——典型的「让数据选算法」而非「预设算法」。
3. **容错纵深与主链路隔离彻底**：打开失败返回 []、迭代异常返回原文、None 归一、目录过滤——表格增强在任何环节失败都不影响既有 PDF 解析，符合「增强项不绑架主链路」的定位。
4. **流程改进自我闭环**：上轮 M1 暴露的「分类表核对靠人肉」缺陷，本轮以「CH 登记必答字段」升格后立即见效（机制行未再漏）——问题定义、对策、验证在一个周期内完成，治理节奏值得保持。
