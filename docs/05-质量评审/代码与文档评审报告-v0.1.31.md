| 版本 | 功能 | 实现评估 |
|------|------|----------|
| 0.1.30 | 常见办公文档支持（CH-053） | ✅ `config.py:38-41` 白名单新增 doc/wps/xls/xlsx/ppt/pptx；`filetype.py:34` classify_ext 归 office 组；`:77-228` 新增 parse_doc（olefile OLE2 UTF-16LE 段提取 + readability 兜底）、parse_wps（同 doc）、parse_xls（xlrd）、parse_xlsx（openpyxl read_only/data_only）、parse_pptx（python-pptx _shape_text 递归含 GROUP/TABLE/text_frame）、parse_office 分发入口（.ppt 返回空由上层提示）；`pipeline.py:38` 改用 parse_office；`requirements.txt:13-17` 含 olefile/xlrd/openpyxl/python-pptx；解析器全容错（损坏/伪装扩展名返回空）；实现规范 |
| 0.1.31 | 未登录轮询 401 修复（CH-056） | ✅ `app.js:187-191` 轮询中 refreshParseStatus 加三重条件：parseEl 存在 + `!parseEl.closest(".hidden")`（解析 Tab 可见）+ `localStorage.getItem("lantai_session")`（已登录）；未登录时不再调用需会话的 /api/settings/parse，消除 401 刷日志；实现规范 |

**结论：0.1.30~0.1.31 实现规范，0 代码 bug。**

0.1.30 办公文档解析器设计要点：
- **parse_office 分发入口**统一按扩展名路由，pipeline 只调一处，扩展性好
- **全容错**：每个解析器 try/except 返回空串，由 pipeline 上层统一提示"未能提取文本"，不阻塞
- **.ppt 诚实降级**：二进制演示文稿暂无纯 Python 提取方案，返回空 + 上层提示，不假装成功
- **parse_doc readability 兜底**：OLE2 UTF-16LE 段提取后用 text_readability ≥ 0.15 判定，噪声过重返回空
- **_shape_text 递归**：pptx 支持 GROUP（分组嵌套）/ TABLE（表格）/ text_frame（文本框），覆盖主要 shape 类型

0.1.31 轮询修复要点：
- **三重条件**精确控制：元素存在 + Tab 可见（非 hidden） + 已登录（localStorage 有 session），未登录时 0 次 401
- 修复精准，不误伤正常登录场景的解析状态刷新
