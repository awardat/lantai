> 修复：测试方案版本基线升 0.1.16，补 GBT 编码不可映射 PDF 的判定/预览 note 用例。

`数据库设计文档.md` 文档头/页脚"V1.3（对应应用 0.1.12）"。0.1.13~0.1.16 表结构未变（无需升版），但版本号标记未跟进当前应用版本。可接受（表结构确未变），但建议补注"0.1.16 表结构无变化"。

**L5-new. 版本记录缺 0.1.14 行**
`版本记录.md` 版本列表 0.1.13 → 0.1.15，无 0.1.14 行（CH-028 已撤销）。release 目录表亦无 0.1.14。撤销后不留版本记录痕迹，与 CH-028 总表"已撤销"标注存在但版本记录中完全消失。建议补一行"0.1.14 | 已撤销 | logo 整体变更（CH-028，用户指示撤销，回退 0.1.13）"以保留历史可追溯性。

**L6-new. 前端 onclick 内联 + esc 不转义引号（v0.1.11 L6 延后项沿用）**
`app.js:160/293/603` 仍以 `esc(...).replace(/'/g,"\\'")` 构造内联 JS。安全性依赖后端 `sanitize_filename` 已去除引号类字符。建议后续改 `data-*` + 事件监听做纵深防御。历史延后项，沿用。

**L7-new. SSE 同步生成器占用线程池 worker 整条流时长（v0.1.11 L7 延后项沿用）**
`chat.py` chat_stream 为 `def` 端点 + 同步 gen + `httpx.Client.stream`，整条流占一个 worker。uvicorn 默认 40 worker，单用户演示无碍。历史延后项，沿用。

**L8-new. `text_readability` 阈值 0.4 为经验值，无注释说明依据**
`filetype.py:96` `READABILITY_THRESHOLD = 0.4`，无注释说明该阈值如何确定（是否经 GBT/Asperger/扫描件样本验证）。0.1.16 自测覆盖了 GBT（判 OCR）与 Asperger/扫描件回归，但阈值 magic number 缺乏依据注释，后续调优无参考。

**L9-new. `pdf_text_layers` 对每页同时跑 pdfminer 与 pypdf（双引擎）有性能开销**
`filetype.py:160-168` 当 pdfminer 提取的页文本可读性不达标时，额外调用 `_pypdf_page_text` 再提取一次。对 GBT 类（每页都不可读）会双倍提取。演示规模（几十页）无感，大文档有开销。可接受（正确性优先），但值得注释标明取舍。

### ℹ️ 提示（非问题）

- **0.1.16 双引擎兜底设计合理**：pdfminer 几何排序优先（阅读顺序还原），可读性不达标时回退 pypdf，仍不达标判图片页走 OCR——既保住 GBT 类 PDF 的正确判定（OCR），又不误伤正常文字 PDF。
