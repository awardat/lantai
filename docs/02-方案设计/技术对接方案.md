# 技术对接方案：兰台（lantai）本地 RAG 知识库

## 1. 技术概述

### 1.1 产品背景

兰台是本地运行的 RAG 知识库演示产品：文档（txt/md/pdf/docx/图片）上传后自动解析入库，自然语言问答带引用来源，数据留在本机。首版（0.1.1）实现 MVP + 文件管理，Windows x64 单机部署。

### 1.2 技术目标

- 两步启动（装依赖/解压 → 运行），浏览器即用，无构建步骤；
- 演示规模（几十~几百切片）检索毫秒级；
- 双 AI Provider（Ollama 本地 / OpenAI 兼容云端）按文件类型可混配，配置即时生效；
- 为档位 3（SSE、对话历史、rerank、hybrid、向量库替换、多跳）与 RBAC、多平台预留扩展点。

## 3. 系统架构

### 3.1 整体架构（前后端分离）

```
浏览器（原生前端单页：业务首页[问答/文档管理] + 配置[设置图标·密码门禁]）
   │ 仅调用 /api/*（JSON）
   ▼
FastAPI 应用（backend/app）
   ├── routers/docs       文档上传/列表/删除/预览
   ├── routers/chat       问答（检索+生成，含 SSE 流式）
   ├── routers/conversations 对话历史（会话 CRUD/消息）
   ├── routers/settings   配置（AI 配置/供应商/token/改密/关于）
   ├── pipeline           解析管线：filetype 路由 → 解析 → 切块 → 向量化 → 入库
   ├── llm / embeddings   双 Provider 调用（OpenAI 兼容协议，含流式）
   ├── store              SQLite + numpy 向量检索（VectorStore 抽象）
   ├── security           密码门禁 / API token / 会话
   └── vendors            预置 AI 供应商目录（URL/能力/推荐模型）
   │
   ├── data/rag.db     SQLite（documents/chunks/settings/api_tokens/conversations/messages）
   └── data/uploads/<doc_id>/  源文件（保留，供 Web 预览）
   │
   └── 外部 AI：Ollama（127.0.0.1:11434）或 OpenAI 兼容云端 API
```

### 3.2 模块划分

| 模块 | 职责 | 说明 |
|------|------|------|
| `config.py` | 路径、端口、版本（0.1.6） | 冻结运行时（PyInstaller）时基于可执行文件目录 |
| `schemas.py` | pydantic 模型 | 上传响应、问答请求/响应、AI 配置、会话/消息等 |
| `llm.py` | 问答调用 | OpenAI 兼容 chat/completions（含流式 chat_stream）；Ollama 走 /v1 |
| `embeddings.py` | 向量化 | OpenAI 兼容 embeddings；支持批量 |
| `chunker.py` | 切块 | 段落感知 + 长度窗口（默认 400/重叠 50） |
| `store.py` | SQLite + 向量 | `VectorStore` 抽象（为 ChromaDB/Milvus 替换预留） |
| `retriever.py` | top-k 检索 | numpy 余弦；返回切片+分数+文档信息 |
| `pipeline.py` | 解析编排 | 上传后异步任务：解析→切块→向量化→入库 |
| `filetype.py` | 文件分类 | 五类判定（含 PDF 文本层检测）与解析器注册 |
| `security.py` | 门禁/token/会话 | PBKDF2、SHA-256、HTTP-only Cookie |
| `vendors.py` | 预置供应商目录 | 9 个供应商：URL/能力声明/推荐模型（0.1.3 起，0.1.33 增 MiMo） |

| `agent_log.py` | 智能体日志（0.1.10） | `data/logs/agent-<时间戳>.log` JSON 行：提示词/思维链/答案截断/token/耗时/上下文 |

### 3.3 解析队列（0.1.18）

上传不再即时同步解析：`task_queue.py` 以 FIFO `queue.Queue` + 固定并发 worker 消费（默认 10），`main.py` lifespan 启动 worker 并恢复排队文档；`set_concurrency` 动态调整（重启 worker）；文档状态新增 `queued`（排队中）。详情见 `docs/03-增长迭代/版本记录.md` 0.1.18 行与 API 说明文档 §6.4。

## 4. AI 接入方案（参考 deepseek-harness-master）

### 4.1 参考来源

`C:\code\dsh-ui\deepseek-harness-master\packages\llm\llm-pi-ai`（DeepSeek Harness 的 LLM 接入层）提供以下可借鉴模式：

- **Provider 路由配置**：`{provider, displayName, baseURL, apiKey(env 引用), models[]}` 注册式管理，设置可动态增删路由、即时生效；
- **多协议实现**：`openai-completions` / `openai-responses` / `anthropic-messages` 三种 wire 协议由统一 Provider 抽象调度；
- **模型能力声明**：模型目录（catalog）声明 `input` 能力（`text` / `image`），视觉模型（如 gpt-4o、claude 系列）标记 image 输入，供"图片类文件走视觉模型"这类路由决策；
- **凭据分离**：API Key 不在构造期注入 Provider，每次请求经凭据解析（`Bearer` 头），支持不同路由不同 Key。

### 4.2 兰台首版接入（简化）

首版统一采用 **OpenAI 兼容协议**（Ollama ≥0.9 亦提供 `/v1` 兼容端点，一套协议双 Provider）：

| 能力 | 端点 | 请求要点 | 响应要点 |
|------|------|----------|----------|
| 问答 | `POST {base}/chat/completions` | `{model, messages:[{role,content}], temperature}` | `choices[0].message.content` |
| 视觉理解（图片/OCR） | 同上 | content 为数组：`[{type:"text",text:提示词},{type:"image_url",image_url:{url:"data:image/png;base64,..."}}]` | 同上 |
| Embedding | `POST {base}/embeddings` | `{model, input:[文本]}` | `data[0].embedding`（浮点数组） |
| 测试连接/模型列表 | `GET {base}/models` | `Authorization: Bearer {key}` | `data[].id` |

- Provider 二选一：`ollama`（默认 `http://127.0.0.1:11434`，走 `/v1`，无 Key）／`openai-compatible`（任意兼容服务）。
- 预置供应商目录（vendors.py，0.1.3 起，0.1.33 扩展）：9 个——Ollama、DeepSeek、通义、智谱、OpenCode Go、Moonshot、**小米 MiMo**（`https://api.xiaomimimo.com/v1`，推荐 `mimo-v2.5-pro`：chat/vision 图片理解、1M 上下文、无 embedding）、硅基流动、OpenAI；配置界面选择即自动填充 URL 与推荐模型。
- 每类模型配置：`{provider, base_url, api_key, model, prompt, temperature}`；**五类文件 + 问答 + embedding** 共 7 组配置，存储于 settings 表（Key 加密）。
- 默认模型（首次启动）：文字/Office/PDF 处理 `qwen2.5:7b`、图片/OCR `llava:7b`、问答 `qwen2.5:7b`、embedding `bge-m3`（1024 维）。
- 提示词默认值：图片类"请详细描述这张图片的内容，包括其中的文字与版式"；OCR 类"请识别图片中的全部文字，保持原文顺序"。
- 超时：问答 120s、embedding 60s、视觉 120s；失败映射为中文错误（连接拒绝/401/404/模型不存在/超时）。

### 4.3 文件类型分类与解析路由

| 分类 | 判定 | 解析方式 | 使用模型 |
|------|------|----------|----------|
| 文字文档 | 扩展名 txt/md | 直接读 UTF-8 文本 | 无需模型（切块后 embedding） |
| Office 文档 | docx / doc / wps / xls / xlsx / ppt / pptx（0.1.30 扩展） | docx：python-docx 段落与表格；doc/wps：olefile（OLE2 `WordDocument` 流 UTF-16LE 段提取，可读性兜底）；xls：xlrd 遍历单元格（日期按 ctype + datemode 转文本 0.1.43）；xlsx：openpyxl（read_only/data_only，日期/百分比按 number_format 转文本 0.1.43）；pptx：python-pptx 递归提取文本框/表格/分组；**表格统一转自然语言（0.1.43 CH-084：首行作表头，数据行转"表格名：表头为值，…"一句，纯规则零 LLM，数字/指标可向量与关键词命中）**；**ppt**：老版二进制演示文稿暂无纯 Python 提取（返回空 → 上层提示"未能提取文本"）；全部解析器容错（损坏/伪装扩展名返回空） | 同上 |
| 文字 PDF | pdf 且文本层字数 > 阈值（如 50） | pypdf 逐页提取文本 | 同上 |
| 图片 | png/jpg/jpeg/webp/bmp/gif | 视觉模型生成内容描述（描述文本再切块向量化） | 该类型配置的模型 |
| 图片 PDF（扫描件） | pdf 且文本层为空/过少 | 逐页提取内嵌图片 → **OCR（视觉模型，或 0.1.46 可选本地 Tesseract 离线识别，`chi_sim+eng`）→ 0.1.47 OCR 噪声清洗（公式/水印页 LaTeX 伪文本等行级过滤）+ 切片去重**；**无内嵌位图（矢量描摹/混合 PDF）时回退整页渲染**（0.1.38，CH-070） | 该类型配置的模型 / 本地 Tesseract |
| 无内嵌位图 PDF 整页渲染（0.1.38，CH-070/R110 落地） | pypdf 提取位图为 0（矢量描摹/去水印 PDF 无 XObject 位图） | `filetype.pdf_render_page_images`：pymupdf `get_pixmap(Matrix(2,2))`（≈144 DPI）整页渲染 PNG → 走正常图片标准化（CH-066）/OCR 通道；有位图场景（GBT TIFF）不触发；渲染也失败时明确提示"请提供位图版文件"（CH-069） | 该类型配置的模型 |
| pdfminer 打开异常回退（0.1.38，CH-072） | pdfminer 对非标 xref/startxref 抛 PDFSyntaxError（阅读器/pypdf 可打开） | `pdf_text_layers` 捕获打开异常 → 单 reader 复用逐页 pypdf 提取 + 可读性判定 | 无模型 |
| PDF 表格转 NL（0.1.44，CH-085） | 电子 PDF 页内存在表格（有线框/无框线 label:value 调查表类） | pdfplumber lattice/text 双策略选非空单元最多的表 → 单元格换行合并（终止符判定）、跨页表头重复/列数+节标题接续判定、跨页行打断逐列拼接 → 键值表（2/4 列）"标签为值"、列式表（≥5 列）"表头为值" NL 行，按页附加到文本（预览与入库同路径）；目录页整表/点线行过滤；None 单元格归一 | 无模型 |
| OCR 文本层空格规整（0.1.38，CH-073） | OCR 扫描件文本层字间空格/换行碎片（"国 务 院"式） | `chunker.clean_ocr_spacing` 删除 CJK 字间空白（英文间距保留），入库/预览统一 | 无模型 |
| 图片格式标准化（0.1.37，CH-066） | 提取的图片实际格式（TIFF/JPEG2000/CCITT 等）不在供应商支持集 | 发送视觉模型前 `normalize_image_for_vision`：Pillow 探测实际格式，非支持集（jpeg/png/bmp/webp/gif）统一转码 JPEG（RGB + quality 90）并同步 MIME；已支持格式原样发送；解码失败透传上游错误——消除"仅支持 jpg\bmp\webp\gif\png"类 400（GBT 20519 标准扫描件 TIFF 实测 23/23 转码） | 该类型配置的模型 |
| 编码不可映射 PDF（0.1.16） | 文本层存在但缺 ToUnicode（复制粘贴乱码，字符码伪文本） | `text_readability` 可读性检测（CJK/英文占比-字符码惩罚）判伪 → 归 pdf_image 走 OCR；pdfminer 空/不可读时先回退 pypdf（可读才采用） | 该类型配置的模型 |

> PDF 页渲染为图片：内嵌位图优先 pypdf 提取页内图片资源（扫描件通常为整页嵌入图）；**0.1.38 起 R110 整页渲染落地**：无内嵌位图（矢量描摹/混合）PDF 由 pymupdf（zoom 2 ≈144 DPI）整页渲染作为 OCR 兜底（CH-070/073），依赖已入 requirements（`pymupdf>=1.28`），详见版本记录与 §6.1 同期变更。
> 文本提取（R117①，0.1.8/0.1.16）：pdfminer layout 几何排序（页眉页脚/页码碎片过滤、基础双栏检测）优先；页文本可读性不达标（`text_readability` < 0.4）时回退 pypdf 提取，仍不可读（编码不可映射）则判为图片页走 OCR——双引擎兜底防字符码伪文本入库；0.1.38（CH-072）起 pdfminer 打开即抛异常（非标 xref）同样回退 pypdf。

## 6. API 接口设计

规范：RESTful + JSON；统一响应 `{code, message, data}`；错误均为中文 message。

### 6.1 文档（免登录）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/docs/upload` | POST | multipart 上传（≤20MB，白名单）；返回文档记录（状态=解析中） |
| `/api/docs` | GET | 文档列表（名称/类型/大小/状态/切片数/时间） |
| `/api/docs/{id}` | GET | 文档详情 |
| `/api/docs/{id}` | DELETE | 删除（级联切片与源文件） |
| `/api/docs/{id}/retry` | POST | 失败文档重新解析（0.1.34）：置 `queued` 重新入队（0.1.35 起原子条件 UPDATE，仅 `failed` 可重试；非 failed 400、不存在 404）；可选 body 二选一——`{"ext":".docx"}` 指定扩展名（0.1.36，白名单内自动更新类型与分类）/ `{"category":"pdf_image"}` 指定文件大类（0.1.37，text/office/pdf_text/pdf_image/image 枚举校验，与 ext 互斥；大类联动扩展名：pdf→.pdf、image→.png、text→.txt、office→保持） |
| `/api/docs/{id}/preview` | GET | 预览文本（txt/md 原文；office 按扩展名分发：docx/doc/wps/xls/xlsx/pptx 提取文本，.ppt 老版二进制提示无法提取；pdf 走浏览器原生查看器） |
| `/api/docs/{id}/preview/raw` | GET | 源文件直出（图片 `Content-Type` 原样；0.1.13 起 `content_disposition_type="inline"`，PDF 供浏览器原生查看器内联显示，不触发下载） |

## 7. 扩展点与档位 3 方案（本期不实现）

### 7.1 流式输出（SSE）【0.1.5 已实现】

`/api/chat` 增加 `stream=true`：后端逐 token 转发（httpx `stream=True` + `sse-starlette` 或原生 StreamingResponse）；前端 EventSource 渲染打字机效果。

> 现状：0.1.5 已实现 `POST /api/chat/stream`（SSE：sources → delta → done），前端 fetch 流式渲染打字机效果；非流式接口保留。

### 7.2 对话历史【0.1.5 已实现】

chunks 检索不变；新增 `conversations` 表（消息序列），提问时携带历史消息进入 context；前端会话树。

> 现状：0.1.5 已实现 conversations/messages 表与 CRUD 接口；提问携带最近 6 条历史消息作为上下文，回答后自动入库；前端支持新建/切换/删除/重命名会话（0.1.6 补重命名）。

### 7.3 rerank 与 hybrid 搜索【0.1.39 已实现，CH-075】

> 现状（0.1.39，R106/R107 落地）：`retriever.retrieve` 扩为**向量 top-20 ∪ BM25 top-20 → RRF 倒数排名融合 → top-k**（hybrid，FTS5 + 中文 bigram 索引，`store.keyword_search`）；embedding 故障自动降级 BM25；设置页「重排」开启时（enabled + rerank 模型）经 `POST {base}/rerank` 交叉编码器精排（失败容错回退）。

### 7.4 向量库替换（ChromaDB/Milvus）

`store.py` 的 `VectorStore` 抽象（`add/delete/search/embedding 维度`）为唯一存储入口；替换 = 新实现 + 配置项 `vector_store: sqlite|chromadb|milvus`。注意：chromadb 依赖较重，需评估 Python 3.14 兼容（或独立服务）。

### 7.5 Docker 部署（仅文档）

`Dockerfile`（python:3.14-slim + 依赖 + 前端静态 + data 卷）+ `docker-compose.yml`（服务 + 可选 ollama 服务）；命令 `docker compose up`。本期不做镜像构建。

### 7.6 RBAC 与多用户（R101/R113）

`security.py` 预留用户表与角色字段：管理员/普通用户；权限点 `doc.upload/doc.delete/chat.ask/settings.*/token.manage/password.change`；配置接口按权限点鉴权；登录（会话）替代密码门禁作为后续演进路径。

### 7.7 多平台（R102）

纯 Python 依赖天然可移植；release 矩阵 `release/lantai-0.1.x-<os>-<arch>/`（win/linux × x64/arm64）；PyInstaller 按平台构建；Linux 下数据目录/权限路径差异在 config.py 中参数化。

### 7.8 专用 OCR 引擎（R110）

> 现状（0.1.50，CH-098 口径更正）：**Tesseract 已部分落地**——作为扫描件 OCR 的本地离线通道（0.1.46 起，`pipeline._ocr_image_tesseract`，设置页「图片 PDF（OCR）」可勾选「使用本地 OCR」，chi_sim+eng，详见 §4.3）；**PaddleOCR/piXEl 等仍评估**——若 Python 3.14 wheel 缺失，以独立进程/容器提供，filetype.py 解析器注册表（`OCR_ENGINE` 接口）接入。

## 8. 版本与发布

### 8.1 版本规则（硬性）

- 首个版本 **0.1.1**；**每次变更第三段 +1**（0.1.1 → 0.1.2 → …）；重大功能变更升第二段（0.2.0），正式发布升第一段（1.0.0）。
- 版本号同步于：`config.py`（`APP_VERSION`）、README、release 目录名。

### 8.2 编译发布（无 setup 安装包，0.1.22 起单轨）

**发布单轨（0.1.22 起，CH-041）**：只发布桌面壳绿色便携目录：

```
release/lantai-shell-0.1.x-windows-x64/
├── lantai-shell.exe      # Tauri 2 壳（双击即用，拉起内嵌服务并显示界面）
├── WebView2Loader.dll    # WebView2 loader（必需随行）
├── portable.marker       # 便携模式标记（配置存程序目录）
├── lantai.exe            # 内嵌服务（PyInstaller one-dir 主程序，壳拉起；兼作调试/直跑入口）
├── _internal/            # 运行库（PyInstaller 自动生成）
├── frontend/             # 前端静态资源（作为数据文件打包）
└── 运行说明.txt
```

- 历史双轨（0.1.1~0.1.21）曾单独发布 `release/lantai-0.1.x-windows-x64/`（lantai.exe 直跑 + 浏览器），保留可回滚，**不再新发**；
- 构建：`pyinstaller --onedir --name lantai --add-data frontend;frontend backend/run.py` + `cargo build --release`（shell/src-tauri，需 mingw64 工具链与 `custom-protocol` feature）；
- 打包 zip：`release/lantai-shell-0.1.x-windows-x64.zip`；**发行物不含 data/**（首次启动自动创建）；
- 数据目录基于可执行文件目录（`config.py` 检测 `sys.frozen`），整体拷贝目录即可迁移。

### 8.3 依赖锁定

`backend/requirements.txt`（运行时）与 `build-requirements.txt`（+ pyinstaller）提交仓库；PyPI 网络不稳定时使用镜像：`pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt`。

## 9. 非功能性需求

### 9.1 性能

| 指标 | 目标 |
|------|------|
| 上传解析（20MB 内） | ≤1 分钟（异步任务，不阻塞其他请求） |
| 检索 | <500ms（几十~几百切片；numpy 全表余弦） |
| 问答 | 超时 120s 上限，超时中文提示 |

### 9.2 安全

- 密码 PBKDF2-HMAC-SHA256（100k 迭代+盐）；连续 5 次失败锁定 1 分钟；
- API token SHA-256 哈希存储；Bearer 鉴权；吊销即时生效；
- 上传：扩展名白名单、大小限制、文件名净化（去除路径分隔符与控制字符）、按 doc_id 分目录存储、目录禁执行；
- 预览接口按文档 ID 白名单读取，防目录遍历；
- Cookie：HTTP-only + SameSite=Lax；AI 配置 Key 加密存储、接口脱敏。

### 9.3 可用性与兼容性

- 全部失败中文提示并给解决建议（Ollama 未启动/模型未拉取/Key 无效/超时等）；
- Chrome/Edge 最新版；Windows 10/11 x64；Python 3.14.7；
- 所有文件读写显式 UTF-8（规避 Windows GBK）。
