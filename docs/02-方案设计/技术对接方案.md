# 技术对接方案：兰台（lantai）本地 RAG 知识库

## 1. 技术概述

### 1.1 产品背景

兰台是本地运行的 RAG 知识库演示产品：文档（txt/md/pdf/docx/图片）上传后自动解析入库，自然语言问答带引用来源，数据留在本机。首版（0.1.1）实现 MVP + 文件管理，Windows x64 单机部署。

### 1.2 技术目标

- 两步启动（装依赖/解压 → 运行），浏览器即用，无构建步骤；
- 演示规模（几十~几百切片）检索毫秒级；
- 双 AI Provider（Ollama 本地 / OpenAI 兼容云端）按文件类型可混配，配置即时生效；
- 为档位 3（SSE、对话历史、rerank、hybrid、向量库替换、多跳）与 RBAC、多平台预留扩展点。

| PDF 解析 | pypdf | 最新 | 纯 Python，文本层提取 + 页面图片检测 |

## 3. 系统架构

### 3.1 整体架构（前后端分离）

```
浏览器（原生前端单页：业务首页[问答/文档管理] + 配置[设置图标·密码门禁]）
   │ 仅调用 /api/*（JSON）
   ▼
FastAPI 应用（backend/app）
   ├── routers/docs    文档上传/列表/删除/预览
   ├── routers/chat    问答（检索+生成）
   ├── routers/settings 配置（AI 配置/token/改密/关于）
   ├── pipeline        解析管线：filetype 路由 → 解析 → 切块 → 向量化 → 入库
   ├── llm / embeddings 双 Provider 调用（OpenAI 兼容协议）
   ├── store           SQLite + numpy 向量检索（VectorStore 抽象）
   └── security        密码门禁 / API token / 会话
   │
   ├── data/rag.db     SQLite（documents/chunks/settings/api_tokens）
   └── data/uploads/<doc_id>/  源文件（保留，供 Web 预览）
   │
   └── 外部 AI：Ollama（127.0.0.1:11434）或 OpenAI 兼容云端 API
```

### 3.2 模块划分

| 模块 | 职责 | 说明 |
|------|------|------|
| `config.py` | 路径、端口、版本（0.1.1） | 冻结运行时（PyInstaller）时基于可执行文件目录 |
| `schemas.py` | pydantic 模型 | 上传响应、问答请求/响应、AI 配置等 |
| `llm.py` | 问答调用 | OpenAI 兼容 chat/completions；Ollama 走 /v1 |
| `embeddings.py` | 向量化 | OpenAI 兼容 embeddings；支持批量 |
| `chunker.py` | 切块 | 段落感知 + 长度窗口（默认 400/重叠 50） |
| `store.py` | SQLite + 向量 | `VectorStore` 抽象（为 ChromaDB/Milvus 替换预留） |
| `retriever.py` | top-k 检索 | numpy 余弦；返回切片+分数+文档信息 |
| `pipeline.py` | 解析编排 | 上传后异步任务：解析→切块→向量化→入库 |
| `filetype.py` | 文件分类 | 五类判定（含 PDF 文本层检测）与解析器注册 |
| `security.py` | 门禁/token/会话 | PBKDF2、SHA-256、HTTP-only Cookie |
| `routers/*` | API 层 | docs/chat/settings/files |

## 4. AI 接入方案（参考 deepseek-harness-master）

### 4.1 参考来源

`C:\code\dsh-ui\deepseek-harness-master\packages\llm\llm-pi-ai`（DeepSeek Harness 的 LLM 接入层）提供以下可借鉴模式：

- **Provider 路由配置**：`{provider, displayName, baseURL, apiKey(env 引用), models[]}` 注册式管理，设置可动态增删路由、即时生效；
- **多协议实现**：`openai-completions` / `openai-responses` / `anthropic-messages` 三种 wire 协议由统一 Provider 抽象调度；
- **模型能力声明**：模型目录（catalog）声明 `input` 能力（`text` / `image`），视觉模型（如 gpt-4o、claude 系列）标记 image 输入，供"图片类文件走视觉模型"这类路由决策；
- **凭据分离**：API Key 不在构造期注入 Provider，每次请求经凭据解析（`Bearer` 头），支持不同路由不同 Key。

### 4.2 兰台首版接入（简化）

首版统一采用 **OpenAI 兼容协议**（Ollama ≥0.9 亦提供 `/v1` 兼容端点，一套协议双 Provider）：

| 能力 | 端点 | 请求要点 | 响应要点 |
|------|------|----------|----------|
| 问答 | `POST {base}/chat/completions` | `{model, messages:[{role,content}], temperature}` | `choices[0].message.content` |
| 视觉理解（图片/OCR） | 同上 | content 为数组：`[{type:"text",text:提示词},{type:"image_url",image_url:{url:"data:image/png;base64,..."}}]` | 同上 |
| Embedding | `POST {base}/embeddings` | `{model, input:[文本]}` | `data[0].embedding`（浮点数组） |
| 测试连接/模型列表 | `GET {base}/models` | `Authorization: Bearer {key}` | `data[].id` |

- Provider 二选一：`ollama`（默认 `http://127.0.0.1:11434`，走 `/v1`，无 Key）／`openai-compatible`（任意兼容服务）。
- 每类模型配置：`{provider, base_url, api_key, model, prompt, temperature}`；**五类文件 + 问答 + embedding** 共 7 组配置，存储于 settings 表（Key 加密）。
- 默认模型（首次启动）：文字/Office/PDF 处理 `qwen2.5:7b`、图片/OCR `llava:7b`、问答 `qwen2.5:7b`、embedding `bge-m3`（1024 维）。
- 提示词默认值：图片类"请详细描述这张图片的内容，包括其中的文字与版式"；OCR 类"请识别图片中的全部文字，保持原文顺序"。
- 超时：问答 120s、embedding 60s、视觉 120s；失败映射为中文错误（连接拒绝/401/404/模型不存在/超时）。

### 4.3 文件类型分类与解析路由

| 分类 | 判定 | 解析方式 | 使用模型 |
|------|------|----------|----------|
| 文字文档 | 扩展名 txt/md | 直接读 UTF-8 文本 | 无需模型（切块后 embedding） |
| Office 文档 | docx | python-docx 提取段落与表格文本 | 同上 |
| 文字 PDF | pdf 且文本层字数 > 阈值（如 50） | pypdf 逐页提取文本 | 同上 |
| 图片 | png/jpg/jpeg/webp/bmp/gif | 视觉模型生成内容描述（描述文本再切块向量化） | 该类型配置的模型 |
| 图片 PDF（扫描件） | pdf 且文本层为空/过少 | 逐页渲染图片 → OCR 模型识别文字 | 该类型配置的模型 |

> PDF 页渲染为图片：首版使用 pypdf 提取页内图片资源（扫描件通常为整页嵌入图）；整页渲染（pymupdf 等）列入 R110 评估，不引入重依赖。

## 5. 数据库设计概要（详见数据库设计文档.md）

| 表 | 用途 | 关键字段 |
|----|------|----------|
| documents | 文档 | id, name, category, ext, size, status, error, chunk_count, created_at |
| chunks | 切片 | id, document_id, seq, text, char_count, embedding BLOB |

## 6. API 接口设计

规范：RESTful + JSON；统一响应 `{code, message, data}`；错误均为中文 message。

### 6.1 文档（免登录）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/docs/upload` | POST | multipart 上传（≤20MB，白名单）；返回文档记录（状态=解析中） |
| `/api/docs` | GET | 文档列表（名称/类型/大小/状态/切片数/时间） |
| `/api/docs/{id}` | GET | 文档详情 |
| `/api/docs/{id}` | DELETE | 删除（级联切片与源文件） |
| `/api/docs/{id}/preview` | GET | 预览文本（txt/md 原文、docx/pdf 提取文本） |
| `/api/docs/{id}/preview/raw` | GET | 源文件直出（图片 `Content-Type` 原样） |

### 6.2 问答（免登录 / 或 Bearer token）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/chat` | POST | `{question, top_k?}` → `{answer, sources:[{doc_id, doc_name, chunk_text, score, category}]}`；支持 `Authorization: Bearer <api_token>` |
| `/api/search` | GET | 仅检索不生成：`?q=&top_k=` → 命中切片+分数（调试/演示用） |

### 6.3 配置（需会话，除 verify 外）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/settings/verify` | POST | `{password}` → 校验通过发 HTTP-only Cookie |
| `/api/settings/ai` | GET | 全部 AI 配置（Key 脱敏） |
| `/api/settings/ai` | PUT | 保存 AI 配置（Key 为空则保留原值） |
| `/api/settings/ai/test` | POST | `{config}` 测试连接，回显模型列表 |
| `/api/settings/password` | POST | `{old_password, new_password}` 修改密码 |
| `/api/settings/tokens` | GET/POST | 列表（脱敏）/ 生成（明文仅返回一次） |
| `/api/settings/tokens/{id}` | DELETE | 吊销 |
| `/api/settings/system/info` | GET | 版本/平台/数据目录（免登录） |

鉴权中间件：配置接口校验会话 Cookie；`/api/chat` 校验会话或 Bearer token（任一通过）。

## 7. 扩展点与档位 3 方案（本期不实现）

### 7.1 流式输出（SSE）【0.1.5 已实现】

`/api/chat` 增加 `stream=true`：后端逐 token 转发（httpx `stream=True` + `sse-starlette` 或原生 StreamingResponse）；前端 EventSource 渲染打字机效果。

> 现状：0.1.5 已实现 `POST /api/chat/stream`（SSE：sources → delta → done），前端 fetch 流式渲染打字机效果；非流式接口保留。

### 7.2 对话历史【0.1.5 已实现】

chunks 检索不变；新增 `conversations` 表（消息序列），提问时携带历史消息进入 context；前端会话树。

> 现状：0.1.5 已实现 conversations/messages 表与 CRUD 接口；提问携带最近 6 条历史消息作为上下文，回答后自动入库；前端支持新建/切换/删除会话。

### 7.3 rerank 与 hybrid 搜索

- rerank：`Retriever` 组合点——向量 top-50 → rerank 模型（如 bge-reranker，经 Ollama/兼容端点）→ 重排取 top-k；
- hybrid：SQLite FTS5 建 BM25 索引，`score = α·cos + β·bm25` 加权融合（`retriever.py` 预留融合函数）。

### 7.4 向量库替换（ChromaDB/Milvus）

`store.py` 的 `VectorStore` 抽象（`add/delete/search/embedding 维度`）为唯一存储入口；替换 = 新实现 + 配置项 `vector_store: sqlite|chromadb|milvus`。注意：chromadb 依赖较重，需评估 Python 3.14 兼容（或独立服务）。

### 7.5 Docker 部署（仅文档）

`Dockerfile`（python:3.14-slim + 依赖 + 前端静态 + data 卷）+ `docker-compose.yml`（服务 + 可选 ollama 服务）；命令 `docker compose up`。本期不做镜像构建。

### 7.6 RBAC 与多用户（R101/R113）

`security.py` 预留用户表与角色字段：管理员/普通用户；权限点 `doc.upload/doc.delete/chat.ask/settings.*/token.manage/password.change`；配置接口按权限点鉴权；登录（会话）替代密码门禁作为后续演进路径。

### 7.7 多平台（R102）

纯 Python 依赖天然可移植；release 矩阵 `release/lantai-0.1.x-<os>-<arch>/`（win/linux × x64/arm64）；PyInstaller 按平台构建；Linux 下数据目录/权限路径差异在 config.py 中参数化。

### 7.8 专用 OCR 引擎（R110）

评估 PaddleOCR/piXEl 等本地 OCR；若 Python 3.14 wheel 缺失，以独立进程/容器提供，filetype.py 解析器注册表（`OCR_ENGINE` 接口）接入。

## 8. 版本与发布

### 8.1 版本规则（硬性）

- 首个版本 **0.1.1**；**每次变更第三段 +1**（0.1.1 → 0.1.2 → …）；重大功能变更升第二段（0.2.0），正式发布升第一段（1.0.0）。
- 版本号同步于：`config.py`（`APP_VERSION`）、README、release 目录名。

### 8.2 编译发布（无 setup 安装包）

```
release/lantai-0.1.1-windows-x64/
├── lantai.exe            # PyInstaller one-dir 主程序（启动 uvicorn + 托管前端）
├── _internal/            # 运行库（PyInstaller 自动生成）
├── frontend/             # 前端静态资源（作为数据文件打包）
├── data/                 # 运行时生成：rag.db、uploads/（首版启动自动创建）
└── 运行说明.txt
```

- 构建：`pyinstaller --onedir --name lantai --add-data frontend;frontend backend/run.py`（入口脚本启动 uvicorn 并打开浏览器）；
- 打包 zip：`release/lantai-0.1.1-windows-x64.zip`；
- 数据目录基于可执行文件目录（`config.py` 检测 `sys.frozen`），整体拷贝目录即可迁移。

### 8.3 依赖锁定

`backend/requirements.txt`（运行时）与 `build-requirements.txt`（+ pyinstaller）提交仓库；PyPI 网络不稳定时使用镜像：`pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt`。

## 9. 非功能性需求

### 9.1 性能

| 指标 | 目标 |
|------|------|
| 上传解析（20MB 内） | ≤1 分钟（异步任务，不阻塞其他请求） |
| 检索 | <500ms（几十~几百切片；numpy 全表余弦） |
| 问答 | 超时 120s 上限，超时中文提示 |

### 9.2 安全

- 密码 PBKDF2-HMAC-SHA256（100k 迭代+盐）；连续 5 次失败锁定 1 分钟；
- API token SHA-256 哈希存储；Bearer 鉴权；吊销即时生效；
- 上传：扩展名白名单、大小限制、文件名净化（uuid 重命名存储）、目录禁执行；
- 预览接口按文档 ID 白名单读取，防目录遍历；
- Cookie：HTTP-only + SameSite=Lax；AI 配置 Key 加密存储、接口脱敏。

### 9.3 可用性与兼容性

- 全部失败中文提示并给解决建议（Ollama 未启动/模型未拉取/Key 无效/超时等）；
- Chrome/Edge 最新版；Windows 10/11 x64；Python 3.14.7；
- 所有文件读写显式 UTF-8（规避 Windows GBK）。

## 10. 项目风险与应对

| 风险 | 应对 |
|------|------|
| PyPI 网络不稳定 | 重试/镜像安装；依赖全部纯 Python 或已有 cp314 wheel |
| Ollama 未安装 | README winget 命令；错误提示引导；云端 Provider 兜底 |
| 视觉模型效果不稳 | 提示词可配置；图片类支持"仅入库不解析"回落 |
| DeepSeek 无 embedding | 配置页提示；embedding 用 Ollama bge-m3 或通义/OpenAI |
| 扫描 PDF 页面图片提取不完整 | pypdf 提取页内图片；R110 评估整页渲染引擎 |
