# 桌面壳方案（lantai-shell）

| 项目 | 内容 |
|------|------|
| 文档版本 | V1.0 |
| 关联需求 | R119（需求池：桌面壳封装） |
| 关联变更 | CH-037 |
| 目标版本 | 0.1.19（已实施） |
| 来源 | 用户需求（2026-08-23）：新增一个壳，业务逻辑复用 `C:\code\dsh-ui`，保留原有架构不变，壳内拉起服务、就绪后打开页面；直接运行 `lantai.exe` 为原有模式，运行壳则单机应用形态，不为服务起单独 cmd 窗口 |

## 1. 目标与原则

- **目标**：把「运行 `lantai.exe` → 浏览器打开 `http://127.0.0.1:8000/`」收敛为单机应用：双击壳 → 自动拉起服务（无独立 cmd 窗口）→ 就绪后内嵌显示兰台 Web UI。
- **原则**：兰台业务（FastAPI 后端 + 原生前端 + SQLite/numpy 检索）**架构不变**；壳为独立桌面层，复用 dsh-ui 成熟实现。

## 3. 总体设计

```
┌───────────────────────────── Windows ─────────────────────────────┐
│  ┌── Tauri 主进程 (Rust) ──────────────────────────────────────┐  │
│  │  terminal.rs   ConPTY 终端（portable-pty + cmd.exe）        │  │
│  │  server.rs     生命周期状态机：就绪探测 / 重启 / 停止 /      │  │
│  │                 keep-alive / 退出清理（按端口杀兜底）        │  │
│  │  zoom.rs       缩放（50–300%，持久化）                      │  │
│  │  job.rs        Windows Job Object（KILL_ON_JOB_CLOSE）      │  │
│  └──────────────────────────────────────────────────────────────┘  │
│  ┌── 主窗口（1280×738，标题「兰台」）───────────────────────────┐   │
│  │  shell 页（tauri 本地资产）→ iframe 内嵌 http://127.0.0.1:8000/ │
│  │  （就绪前显示启动遮罩：logo + 状态 + 内嵌只读终端）           │   │
│  └──────────────────────────────────────────────────────────────┘   │
│  cmd.exe（ConPTY，无窗口）── 自动喂入 `lantai.exe --server`         │
└─────────────────────────────────────────────────────────────────────┘
```

### 启动流程状态机

```
[启动] ──▶ BOOT（启动遮罩 + 自动执行 lantai.exe --server）
            （后台 500ms 轮询 HTTP 8000；端口已监听 → 直接连接）
              │  HTTP 200 就绪（默认超时 120s）
              ▼
[READY] ◀─── iframe 加载 http://127.0.0.1:8000/；终端收起为右下角按钮
              │  点击按钮 → 终端面板（日志 / 手动输入 / 重启 / 停止）
              ▼
[FAILED/STOPPED] ── 按钮红/灰 + 提示；「重新启动」
```

### 关键设计决策

| 决策点 | 结论 | 理由 |
|--------|------|------|
| 壳框架 | Tauri 2（复用 dsh-ui） | 轻量（数 MB）、WebView2 系统内置、单窗口+iframe 方案已充分验证 |
| 窗口架构 | 单窗口 + iframe | Windows 第二个 WebView2 窗口合成不可用（dsh-ui 实测） |
| 服务进程形态 | ConPTY 承载 cmd.exe，窗口不可见 | 满足"无独立 cmd 窗口"；输出经 IPC 到前端 xterm |
| 就绪判定 | TCP 监听即直连；启动路径 HTTP 200 为准 | 双通道 + 终端失败特征快速失败 |
| 退出清理 | Job Object（KILL_ON_JOB_CLOSE）整树终止 | 关壳即结束服务，无残留 |
| 工作目录 | 设置留空 = 壳程序所在目录 | 兰台冻结模式数据目录基于 exe 位置，与 cwd 无关 |
| 发布形态 | 绿色便携目录（不建 setup），**0.1.22 起为唯一发布形态（单轨，CH-041）** | 沿用兰台发布规则；壳 + 服务同目录，双击即用 |
| 服务启动方式 | `lantai.exe --server`（新增参数） | 直接运行 lantai.exe 保持原控制台模式不变（壳目录内保留，兼作调试/直跑入口） |

### 兰台侧改造（最小侵入）

- `backend/run.py` 新增 `--server` 参数：不自动 `webbrowser.open`，其余不变。

### 壳工程（shell/）

- 复用 dsh-ui：src-tauri（Rust 源码）+ ui（Vite/TS/xterm）+ package.json/node_modules
- 改造：启动命令默认 `lantai.exe --server`、端口 8000、工作目录默认壳目录、删除 dsh 专属逻辑（可用性检测/首次下载提示/会话 workspace 跟随/代理 UI）、品牌（产品名 lantai_shell、identifier com.lantai.app、窗口标题「兰台」、「兰」字图标）
- 版本号与兰台同体系（当前 0.1.19），同步三处：tauri.conf.json / Cargo.toml / package.json

## 4. 验收标准

1. 双击 `lantai-shell.exe`：无 cmd 窗口弹出；启动画面显示服务日志；就绪后主界面显示兰台 Web UI（8000 端口）
2. 终端浮层可查看日志、手动输入、重启/停止服务
3. 关闭壳窗口 → 服务进程（lantai.exe/cmd）全部结束（8000 端口释放），无残留进程
4. 直接运行 `release/lantai-0.1.19-windows-x64/lantai.exe` 仍为原控制台模式（自动开浏览器）
5. 重复启动壳只唤起一个实例
6. 便携目录整体拷贝到其他路径后双击仍可用（数据目录随服务 exe 走）

## 5. 风险与对策

| 风险 | 对策 |
|------|------|
| 8000 端口被外部进程占用 | 壳探测到监听即直连并提示；设置页可改端口 |
| WebView2 缺失（罕见） | Win10/11 系统内置 |
| GNU 链接警告 `.rsrc merge failure` | 无害，可忽略 |
| 壳与兰台版本不同步 | 同版本号体系 + 发布清单核对 |

## 6. 构建与发布

```powershell
cd C:\code\lantai\shell
npm run build:ui                       # → ui/dist
$env:CARGO_TARGET_DIR='C:\code\dsh-ui\src-tauri\target'   # 复用缓存（可选）
$env:PATH="C:\code\dsh-ui\.tools\mingw64\bin;$env:PATH"
cd src-tauri && cargo build --release  # → lantai-shell.exe
```

发布组装（**单轨，0.1.22 起，CH-041/CH-044**）：`release/lantai-shell-0.1.x-windows-x64/` = 壳 exe + WebView2Loader.dll + portable.marker + 兰台服务 one-dir 全部内容（服务版目录/zip 不再发布，**release 下不留服务版中间产物**）；**发布统一走 `scripts/build_release.ps1`**（PyInstaller → 组装 → 清理 → zip → 发行物校验：无 data/、无 settings.json、无服务版目录残留）；压缩 zip。
