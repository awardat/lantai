## 二、需求详情

### R001: 文档上传（txt/md/pdf/docx/图片，≤20MB）

**类型**: 新功能 ｜ **优先级**: P0 ｜ **版本归属**: 0.1.1 ｜ **来源**: 用户确认

**描述**: 文档管理页上传本地文件，扩展名白名单：`txt md pdf docx png jpg jpeg webp bmp gif`；单文件 ≤20MB；同名文件允许重复上传（各自独立文档记录）；上传后进入异步解析管线。

**验收标准**: 白名单外类型与超限文件被拒并中文提示；上传成功即出现在文档列表（状态=解析中）。

### R002: 按文件类型解析

**类型**: 新功能 ｜ **优先级**: P0 ｜ **版本归属**: 0.1.1 ｜ **来源**: 用户确认

**描述**: 解析管线按文件类型路由：文字文档（txt/md）直接读文本；Office（docx）用 python-docx 提取文本与表格；文字 PDF 用 pypdf 提取文本层；图片（png/jpg/jpeg/webp/bmp/gif）调用**视觉模型**生成内容描述；图片 PDF（无文本层/扫描件）按页走 **OCR 模型**（视觉模型识别）。各类型所用模型来自该类型自己的 AI 配置（R008）。

**验收标准**: 五类文件均能产出可检索文本；无文本层 PDF 自动走 OCR 通道；解析失败记录原因并提示。

### R003: 切块与向量化入库

**类型**: 新功能 ｜ **优先级**: P0 ｜ **版本归属**: 0.1.1 ｜ **来源**: 用户确认

**描述**: 解析文本按长度切块（默认约 400 字符/块，重叠 50 字符，段落感知），逐块调用全局 embedding 模型向量化，写入 SQLite（chunks 表，numpy 存储向量）。

**验收标准**: 文档入库后切片数正确；重复上传可分别检索；向量维度与模型一致（bge-m3=1024 等）。

### R004: 文档列表 / 删除

**类型**: 新功能 ｜ **优先级**: P0 ｜ **版本归属**: 0.1.1 ｜ **来源**: 用户确认

**描述**: 文档管理页列表展示：名称、类型、大小、状态（解析中/已就绪/失败）、切片数、上传时间；删除时级联删除其全部切片向量与上传源文件。

**验收标准**: 删除后文档、切片、源文件均不可再检索/预览；失败文档可删除重传。

### R005: top-k 检索 + 相似度分数

**类型**: 新功能 ｜ **优先级**: P0 ｜ **版本归属**: 0.1.1 ｜ **来源**: 用户确认

**描述**: 问题先 embedding，再对全库切片做 numpy 余弦相似度检索，返回 top-k（默认 5）切片及相似度分数（0~1）。

**验收标准**: 演示规模（几十~几百切片）检索响应 <500ms；分数按降序排列。

### R006: 问答 + 引用来源

**类型**: 新功能 ｜ **优先级**: P0 ｜ **版本归属**: 0.1.1 ｜ **来源**: 用户确认

**描述**: 问答页输入问题 → 检索 top-k 切片 → 拼接上下文调用全局问答模型生成答案；响应包含引用来源列表（文档名、切片文本、相似度、预览链接）。系统提示词要求模型仅依据上下文回答、无法回答时明确说明。

**验收标准**: 答案带来源卡片；无可用上下文时模型不编造；问答模型未配置/不可达时给出中文错误。

### R007: 保留源文件 + Web 内预览

**类型**: 新功能 ｜ **优先级**: P0 ｜ **版本归属**: 0.1.1 ｜ **来源**: 用户确认

**描述**: 上传源文件保留于 `backend/data/uploads/<文档ID>/`；提供预览接口：txt/md 原文；docx 提取文本渲染；PDF 提取文本（扫描页提示"本页为图片，未 OCR"或展示图片）；图片直接展示。问答/检索结果中点击来源可 Web 内预览。

**验收标准**: 五类文件均可预览；预览不依赖外部服务；源文件删除后预览失效。

### R008: 按文件类型配置不同 AI

**类型**: 新功能 ｜ **优先级**: P0 ｜ **版本归属**: 0.1.1 ｜ **来源**: 用户确认

**描述**: 设置页「AI 配置」：**五类文件**（文字文档 / Office 文档 / 文字 PDF / 图片 / 图片 PDF·OCR）各自配置 `provider + base_url + API Key + 模型名 + 提示词`；另设全局**问答模型**与全局 **embedding 模型**。配置保存即时生效（解析/问答按最新配置执行）。图片类默认模型为视觉模型（如 llava、qwen2.5vl、gpt-4o 等）。

**验收标准**: 修改某一类型模型后重新上传该类型文档生效；不同类型可用不同 Provider（如图片走云端、文字走本地）。

### R009: 双 Provider：Ollama / OpenAI 兼容 API

**类型**: 新功能 ｜ **优先级**: P0 ｜ **版本归属**: 0.1.1 ｜ **来源**: 用户确认

**描述**: Provider 二选一（可混合）：`ollama`（默认 `http://127.0.0.1:11434`，无需 Key）与 `openai-compatible`（任意 OpenAI 兼容 base_url + API Key）。协议统一为 OpenAI 兼容（`/chat/completions`、`/embeddings`），Ollama 亦提供 `/v1` 兼容端点。设置页提供"测试连接"按钮（列出模型）。

**验收标准**: 两种 Provider 均可完成问答与 embedding；未启动/Key 错误时提示具体原因。

### R010: 配置功能密码门禁

**类型**: 新功能 ｜ **优先级**: P0 ｜ **版本归属**: 0.1.1 ｜ **来源**: 用户确认

**描述**: 前端业务功能为首页（问答/文档管理），右上角设置图标进入配置功能；首次进入要求输入密码，默认 `Admin#123`，可修改（R012）。密码 PBKDF2 加盐哈希存储于 settings 表；校验通过后发放短时会话（HTTP-only Cookie），业务接口不受限（单用户演示）。

**验收标准**: 未输密码无法看到/调用配置内容；错误密码提示；修改密码后旧密码失效。

### R011: API token 生成 / 吊销

**类型**: 新功能 ｜ **优先级**: P0 ｜ **版本归属**: 0.1.1 ｜ **来源**: 用户确认

**描述**: 设置页生成 API token（前缀 `lt-`，明文仅展示一次），用于外部调用 `POST /api/chat` 等接口（`Authorization: Bearer`）；服务端只存 SHA-256 哈希；支持命名、吊销。

**验收标准**: 生成的 token 可调用问答接口；吊销后立即失效；列表不展示明文。

### R012: 修改密码

**类型**: 新功能 ｜ **优先级**: P0 ｜ **版本归属**: 0.1.1 ｜ **来源**: 用户确认

**描述**: 配置页「修改密码」：输入旧密码 + 新密码（≥8 位）两次确认；成功即生效。

**验收标准**: 旧密码错误拒绝；新密码过短拒绝；修改后旧会话失效需重新验证。

### R013: 友好中文错误提示

**类型**: 功能优化 ｜ **优先级**: P0 ｜ **版本归属**: 0.1.1 ｜ **来源**: 用户确认

**描述**: 后端统一错误响应 `{code, message}`，前端 toast 展示中文提示：Ollama 未启动、模型未拉取、API Key 无效、网络超时、文件类型不支持、解析失败等。

**验收标准**: 覆盖主要失败场景，提示含解决建议（如"请先 `ollama pull bge-m3`"）。

### R014: 前后端分离 + 业务首页 + 设置图标入口

**类型**: 新功能 ｜ **优先级**: P0 ｜ **版本归属**: 0.1.1 ｜ **来源**: 用户确认

**描述**: 后端纯 API（`/api/*`），前端原生单页（HTML/CSS/JS，无构建步骤）由 FastAPI 托管；前端分**业务功能**（首页：问答、文档管理两个 Tab）与**配置功能**（设置图标进入，密码门禁）。

**验收标准**: 前端仅通过 `/api/*` 取数；业务功能直达，无密码干扰；配置入口为设置图标。
